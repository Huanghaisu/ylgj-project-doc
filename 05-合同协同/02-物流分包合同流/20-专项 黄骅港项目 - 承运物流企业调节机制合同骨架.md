# 黄骅港项目承运物流企业调节机制合同骨架

## 一、合同定位

用于承接黄骅港项目专项模型下，合同物流企业向承运物流企业输出的专项分包合同逻辑。

本合同骨架重点解决价格波动收益与风险调节、执行阈值判断、缩量停运机制和专项清分接口问题。

## 二、合同主体建议

1. 甲方：汉江数智科技发展(襄阳)有限公司。
2. 乙方：承运物流企业。

## 三、核心条款模块

### （一）项目范围

明确运输线路、货类、运量区间、执行周期、车辆组织要求和返程组织原则。

### （二）专项模型适用条款

明确本合同适用黄骅港项目专项模型，价格波动收益与风险按专项约定执行，不外推至其他项目。

### （三）价格机制条款

明确以下内容：

1. 实际到手结算吨价确认口径。
2. 承运分包结算总价确认口径。
3. 承运调节线确认方式。
4. 项目总执行边界线与承运调节线的关系。
5. 价格变化情况下的通知和确认程序。

### （四）非承运完全成本与承运分包口径条款

明确以下内容：

1. 非承运完全成本识别口径。
2. 承运分包结算总价识别口径。
3. 项目总成本=非承运完全成本+承运分包结算总价的计算关系。

### （五）承运物流企业调节职责条款

明确以下内容：

1. 乙方在可执行区间内承担执行层价格波动收益与风险调节职责。
2. 乙方在运价上行时可按约定享有弹性收益。
3. 当实际到手结算吨价低于或等于承运调节线但仍高于项目总执行边界线时，乙方持续承担执行层波动。
4. 乙方在项目总执行边界线未被击穿前，不以承运调节线被击穿为由当然要求项目停做。
5. 当项目总执行边界线被击穿时，乙方配合启动项目级缩量、暂停或停运重谈。

### （六）运费调节机制条款

明确以下内容：

1. 执行边界触发条件。
2. 执行边界判断主体。
3. 执行边界触发后的任务处理顺序。
4. 缩量执行、暂停执行和恢复执行条件。

并明确双层运费调节顺序：

1. 先判断承运调节线。
2. 再判断项目总执行边界线。
3. 只有项目总执行边界线被击穿后，才进入项目级停新增、保在途。

### （七）对账与清分接口条款

明确以下内容：

1. 对账基础资料。
2. 回款确认后的承运分包结算总价确认方式。
3. 承运调节线确认方式。
4. 乙方弹性收益或波动吸收结果确认方式。

### （八）责任边界条款

明确以下内容：

1. 乙方承担执行层组织、运输执行和专项调节义务。
2. 乙方不承担甲方对外总包合同中未传导或未对应配置收益的额外义务。
3. 甲方不向乙方转嫁未形成专项约定的无限价格风险。

### （九）退出与恢复条款

明确以下内容：

1. 进入执行边界区间后的缩量和暂停安排。
2. 恢复执行的复核条件。
3. 重大波动下的重谈程序。

并明确：

1. 乙方进入执行层自担波动区时，默认持续承担波动，不单列强制重谈时点。
2. 只有项目总执行边界线被击穿后，才进入项目级停运重谈。

## 四、附件建议

1. 运输计划附件。
2. 实际到手结算吨价确认附件。
3. 承运分包结算总价确认附件。
4. 双层运费调节测算附件。
5. 执行边界触发与恢复流程附件。
