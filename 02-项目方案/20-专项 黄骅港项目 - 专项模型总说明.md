# 黄骅港项目专项模型总说明

## 一、专项设立结论

设立黄骅港项目专项模型。

本专项模型用于承接黄骅港项目当前货主制式合同变更带来的业务、合同、清分、风控与流程变化。专项模型仅适用于黄骅港项目当前货主合同条件，不上升为全项目通用模型，不替代现有 `00-基线` 和 `10-模板` 体系。

## 二、专项设立原因

确认现有通用模型不能直接覆盖黄骅港项目当前条件。

现阶段货主制式合同存在以下特征：

1. 未锁定物流运费价格。
2. 未稳定提供最低运价保障。
3. 未形成明确调价机制。
4. 可能要求合同物流企业承担与收益不匹配的责任。

在上述条件下，若继续沿用原经营逻辑，项目将同时面临收入端不确定、成本端刚性、责任端失衡和流程端缺少熔断抓手等问题。基于此，需单独建立黄骅港专项模型，对项目成立前提、价格风险承接、清分顺序、运费调节机制和责任边界进行专项重构。

## 三、专项模型适用边界

限定本专项模型适用范围。

1. 适用于黄骅港项目当前货主制式合同条件。
2. 适用于货主不锁运价、最低运价保障不足或调价机制缺失的场景。
3. 适用于黄骅港项目当前“总包承接 + 协同运力组织 + 专项清分 + 熔断控制”的执行结构。
4. 不适用于其他港口、矿区、厂区项目。
5. 不直接写入 `00-基线`、`10-模板` 或角色词典主定义。

## 四、专项模型核心定义

固定专项模型的五项核心定义。

### （一）合同物流企业定位

保留合同物流企业总包承接方、业务组织方和履约管理方定位。

汉江数智科技发展(襄阳)有限公司作为合同物流企业，继续负责对接货主需求、承接总包业务、组织下游执行、统筹运输计划、推进对账回款并形成项目经营闭环。

### （二）平台公司定位

保留平台公司运力组织、调度协同、数据支持和过程协同定位。

长江数联物流信息(湖北)股份有限公司作为平台公司，继续围绕车辆资源组织、调度协同、数据留痕、过程跟踪和清分支持提供协同能力。

### （三）持车服务公司定位

保留持车服务公司资产供给方定位。

持车服务公司继续围绕车辆供给、资产管理和资产侧配套支撑提供资源保障。

### （四）地方平台公司、物流服务公司定位

保留地方平台公司、物流服务公司分包协同和执行层定位。

地方平台公司继续承担区域协调、分包组织和在地衔接职能；物流服务公司继续承担现场运输执行、司机组织和日常作业管理职能。

### （五）承运物流企业专项附加定义

新增承运物流企业价格波动收益与风险调节层定义。

在黄骅港专项模型下，承运物流企业在执行层新增承担价格波动收益与风险调节功能。承运物流企业在满足项目执行条件时享有相应弹性收益；在市场运价波动时，按专项约定吸收执行层波动风险；在市场运价跌破固定成本和硬性费用时，按专项机制触发缩量、停运或重谈安排。

## 五、专项模型成立前提

明确项目继续执行的前提条件。

1. 确认货主需求真实存在，运量、线路和装卸场景具备执行基础。
2. 确认市场运价处于可执行区间。
3. 确认市场运价能够覆盖固定成本、硬性费用并保留最低安全边际。
4. 确认承运物流企业同意按专项机制承接执行层价格波动收益和风险。
5. 确认合同物流企业不承担与收益明显不对等的责任。
6. 确认专项流程中已设置价格校验、阈值判断、熔断触发、决策通知和恢复机制。

## 六、可执行区间与执行边界区间

设定专项模型运行区间。

### （一）可执行区间

认定市场运价覆盖固定成本、硬性费用并保留最低安全边际时，项目处于可执行区间。项目可按专项模型继续组织投放、接单、排班和履约。

### （二）执行边界区间

认定市场运价低于固定成本和硬性费用时，项目进入执行边界区间。项目不得继续按原投放规模、原执行节奏或原清分顺序运行，应立即启动专项熔断流程。

## 七、专项模型对整体体系的保护要求

1. 不修改 `02-项目方案` 下 `10-模板` 系列文件。
2. 不修改 `04-财务模型` 下 `00-基线` 文件。
3. 不修改 `06-工具（skills）/角色词典.md` 的主定义。
4. 不将黄骅港专项运费调节机制写成所有项目的统一规则。
5. 凡引用专项逻辑的文件，均应注明“以黄骅港专项模型文件为准”。
